# Поддержка, развитие характеров и выпуск

## Где править

| Изменение | Источник |
| --- | --- |
| Общая точность, темп, доступ, память | `src/common.md` |
| Математика и переключение героев | `src/math.md` |
| Английский | `src/english.md` |
| Голос Тео/Графа/Ники и краткая версия | `profiles/*_PROFILE.md` |
| Номер редакции | `VERSION` и Profile-Version в трёх профилях |
| Исходная авторская ДНК/продукт | Новая точная копия с записью в `provenance/SOURCES.json`; старый статус не повышать автоматически |

В готовые `products/*/PROMPT.txt` вручную не править: изменение потеряется при сборке. `scripts/build.py` включает краткие описания из маркеров SHORT_PROFILE и предметный слой, затем добавляет закреплённые raw-ссылки.

## Новый характер или решение автора

1. Проверить точный текущий источник и его статус. История чата сама не заменяет файл-владелец; явное новое авторское решение фиксируется с датой и ролью.
2. Разделить: литературный факт, учебная адаптация и новая гипотеза. Изменение внешности не является изменением математики или характера.
3. Править затронутый профиль, устранить противоречие в кратком описании. Не копировать закрытые главы ради обоснования профиля.
4. Поднять версию, собрать продукты и прогнать проверки/затронутые приёмочные сценарии. Книжная резкость не переносится в обращение к ученику.
5. Обновить CHANGELOG, статус и отчёт. Перед записью проверить чужие изменения, не делать force-push.

## Проверка и выпуск

```bash
python3 scripts/build.py
python3 scripts/verify.py
```

Для реальной модельной проверки: сценарии в `tests/cases.json`. Для каждого независимый новый чат с полным промптом; для многоходовых сценариев сохранить все сообщения. Записать фактическую модель/режим/дату, версии, доступ к web/audio/files, полный ответ и оценки по рубрике. Не считать незапущенный сценарий пройденным. После изменения голоса повторить предметные сценарии: стиль не должен снизить точность.

Опубликованная версия закрепляется тегом `v<номер>`; промпты используют raw-файлы этого тега. Перед публикацией убедиться, что тег ещё не занят. Теги выпущенных редакций не передвигать. После push проверить raw-файлы по сети и хешам. На main находятся текущие файлы разработки; для запуска пользователь копирует готовый промпт нужного выпуска.

Серьёзные ошибки точности, унижение, выдуманный доступ/память, раскрытие ответа в режиме самостоятельной работы — блокеры выпуска как проверенного. До живых прогонов статус остаётся RC, даже если текст и автоматические проверки готовы. Не обещать измеримый результат обучения без исследования.

## Пользовательское обновление

Пользователь забирает новый PROMPT.txt и переносит свою локальную заметку, лучше в новый чат. Никакого автоматического обновления уже запущенных чатов нет. Не смешивать старое ядро с новым несовместимым профилем. В память не записывать переписку, контакты, школу и другие личные данные. Эта открытая библиотека не принимает личные логи учеников.

## Совместимость и условия распространения

Поддерживается текстовый перенос, а не API конкретного провайдера. Браузер и аудио необязательны; файлы удобны, но не обязательны. Не открывать закрытые учебные источники и не менять их видимость. Не добавлять лицензию на чужие банки задач, персонажей или текст от имени автора без отдельного решения. Публичность репозитория сама по себе не равна свободной коммерческой лицензии.
